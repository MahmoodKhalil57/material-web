Dialogs

Dialogs provide important prompts in a user flow.

View as Markdown

Install with shadcn/ui: npx shadcn@latest add https://material-web.dev/3.0/r/md-dialog.json (setup)

Usage guidelines

Link to “Usage guidelines” #
  • Use them sparingly. A dialog interrupts people to ask for a decision or to show critical information, so it blocks the rest of the app until it is dismissed.
  • Pick the right priority. For low or medium priority information, use a snackbar instead.
  • Choose basic or full-screen. Use a basic dialog by default. A full-screen dialog suits compact windows with a lot of content.
  • Order the actions. Put the dismissive action first and the confirming action last.

Anatomy

Link to “Anatomy” #

A dialog has an optional icon and headline, supporting content, and actions.

Examples

Link to “Examples” #

With an icon

Link to “With an icon” #

Put an md-gb-icon in the icon slot to center the headline under a hero icon.

Full-screen

Link to “Full-screen” #

Set full-screen for a dialog that fills a compact window, with a close button and the confirming action in its header. Above compact sizes it falls back to a basic dialog; add always-full-screen to keep it.

Return value

Link to “Return value” #

A button's value becomes the dialog's returnValue when it closes the dialog through its form. Read it in the closed event.

Opening and closing

Link to “Opening and closing” #

Open and close a dialog with show() and close(), or by setting open. Both methods return a promise that resolves after the animation. Cancel the cancel event to keep the dialog open.

Accessibility

Link to “Accessibility” #
  • The headline names the dialog. Add aria-label to a dialog without a headline.
  • A basic dialog is an alert dialog (role="alertdialog") by default, as M3 asks for on the web. Set type="dialog" for a plain dialog.
  • Focus moves into the dialog and Tab cycles inside it. Escape closes it and focus returns to what opened it.
  • Label buttons and fields inside the dialog as you would elsewhere. In a full-screen dialog, set close-label to name the close button.

API reference

Link to “API reference” #

<md-gb-dialog>

Link to “<md-gb-dialog>” #

A Material Design dialog component.

Properties

Link to “Properties” #
Property Attribute Type Default
alwaysFullScreen
Full-screen dialogs are for compact windows only (dialogs.md: use a basic dialog at medium and expanded). So full-screen applies at compact windows and the dialog is a basic dialog above, with the same slots. The host gets adaptive-basic while it falls back. Set always-full-screen to keep the full-screen variant at every window size.		 always-full-screen boolean false
closeLabel
Accessible label of the full-screen close icon button.		 close-label string 'Close'
fullScreen
Uses the full-screen variant: the dialog fills the window, with a header holding a close icon button, the headline and the confirm action. Meant for compact windows; use a basic dialog at larger breakpoints.		 full-screen boolean false
noFocusTrap
Turns off focus trapping, which keeps Tab and Shift+Tab cycling inside the dialog. Trapping is recommended for accessibility.		 no-focus-trap boolean false
open
Opens the dialog when set to true and closes it when set to false.		 open boolean
quick
Skips the opening and closing animations.		 quick boolean false
returnValue
The dialog's return value, usually which button closed it. Set by close(returnValue) and by <form method="dialog"> submitters' value. Canceling (Escape, scrim, close button) leaves it unchanged. https://developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/returnValue		 string ''
type
The dialog's accessibility role. alert (role="alertdialog") or dialog (role="dialog"). When empty, basic dialogs are alert dialogs, as the spec asks for on the web, and full-screen dialogs are dialogs.		 type DialogType ''

Slots

Link to “Slots” #
Slot Description
default The supporting text or custom content (lists, form fields). Scrolls between the pinned headline and actions when it overflows.
actions The action buttons, dismissive first and confirming last. Basic: end-aligned below the content. Full-screen: the confirm action at the end of the header.
headline The headline. Labels the dialog (aria-labelledby).
icon An optional hero icon above the headline (basic only). Centers the headline.

Events

Link to “Events” #
Event Description
cancel
Event		 Fired when the dialog is canceled with Escape, a scrim click or the full-screen close button. Cancelable; canceling keeps the dialog open.
close
Event		 Fired when the dialog begins closing; returnValue is already set. Cancelable.
closed
Event		 Fired when the dialog has closed and animations finished.
open
Event		 Fired when the dialog begins opening. Cancelable.
opened
Event		 Fired when the dialog has opened and animations finished.

Methods

Link to “Methods” #
Method Description
close
(returnValue?: string, reason?: string) => Promise<void>		 Closes the dialog and fires a cancelable close event, then closed after the exit animation. Focus returns to the element focused before the dialog opened.
show
() => Promise<void>		 Opens the dialog as a modal and fires a cancelable open event, then opened after the enter animation. Focus moves to the first child with an autofocus attribute, else the first focusable element, else the dialog.
