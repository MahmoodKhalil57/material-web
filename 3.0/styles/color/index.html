Color

Color creates meaning and communicates hierarchy, state, and brand.

View as Markdown

Color scheme

Link to “Color scheme” #

The page follows the subpages of the M3 color guidance in order. All imports come from @material/web/labs/gb/styles/color/.

Color system

Link to “Color system” #

The system turns a few inputs into a complete, accessible set of colors. Dynamic color starts from a source color, runs it through a scheme algorithm, derives five key colors (primary, secondary, tertiary, neutral, neutral variant) plus error, builds a tonal palette for each in HCT (hue, chroma, tone), and assigns tones to color roles. Roles come with a pairing rule: a color and its on- color are chosen so text and icons stay legible. Each role has three contrast levels (standard, medium, high), so the same scheme can serve people who need more contrast.

In labs/gb:

  • md-color-tokens.css is the static baseline: every role as a --md-sys-color-<role> custom property, with light and dark values.
  • md-color-tokens-contrast.css adds medium and high contrast. High contrast follows prefers-contrast: more, and .md-contrast-standard, .md-contrast-medium and .md-contrast-high select a level for a subtree.
  • md-color-tokens-full.css also declares the reference palette (--md-ref-palette-*), the tonal palettes the roles are picked from.
  • dynamic-color.ts runs the generation steps at runtime with Material Color Utilities (see Dynamic color below).

The new tone-based surface roles (container levels, dim, and bright) and the fixed accent roles from the latest spec are all part of the tokens, so nothing extra is needed to use them. HCT is also available as a small API (see Advanced customization).

Color roles

Link to “Color roles” #

A role is a named job for a color, not a specific hue. Components read roles (primary, surface-container) instead of hex values, so a new scheme re-themes everything. The spec groups them as accent roles (primary, secondary, tertiary, error, each with on-, -container and on-container variants), surface roles with on-surface and on-surface-variant, outline roles, inverse roles, and add-on roles: fixed accents and bright and dim surfaces. Layer from lower to higher emphasis, and always put on- content on its matching background.

Role Tokens
Primary, secondary, tertiary --md-sys-color-<accent>, -on-<accent>, -<accent>-container, -on-<accent>-container
Fixed accents --md-sys-color-<accent>-fixed, -<accent>-fixed-dim, -on-<accent>-fixed, -on-<accent>-fixed-variant
Error --md-sys-color-error, -on-error, -error-container, -on-error-container
Surface --md-sys-color-surface, -surface-dim, -surface-bright, -surface-container-lowest through -surface-container-highest, -on-surface, -on-surface-variant
Outline --md-sys-color-outline, -outline-variant
Inverse --md-sys-color-inverse-surface, -inverse-on-surface, -inverse-primary
Other --md-sys-color-scrim, -shadow

Fixed accents keep the same value in light and dark themes, for content that should not flip, such as a brand surface. Use surface-dim and surface-bright for areas that stay darker or brighter than the main surface in both themes.

Light and dark

Link to “Light and dark” #

The tokens use light-dark(), so they follow the standard color-scheme property. Where light-dark() is not available, the Baseline fallback keeps the light values and switches to the dark values with prefers-color-scheme.

The deprecated background and surface-tint roles are not defined; use surface and a surface container instead.

Choosing a scheme

Link to “Choosing a scheme” #

Pick static color when you want a fixed, predictable palette: a brand identity, a product with a strict visual identity, or a small, controlled UI. Pick dynamic color when the palette should come from the person or the content: a wallpaper, a profile color, an album cover. You can also mix both: a dynamic scheme for most of the UI and static colors for brand and semantic meaning.

In labs/gb that is a choice of which stylesheet or function you load:

  • Static: import md-color-tokens.css (and md-color-tokens-contrast.css if you want contrast levels). No JavaScript.
  • Dynamic: call themeFromSource(), themeFromImage() or applyTheme(), which output the same custom properties and override the static ones.

Static color

Link to “Static color” #

The spec has two kinds. Baseline is the default purple scheme, ready to use and a good starting point for prototypes. Custom brand keeps the same roles but replaces the key colors with your brand colors, usually exported from the Material Theme Builder or a design tool.

Baseline in labs/gb is the default stylesheet. It is also part of m3Styles, which adoptStyles() loads.

For a custom brand scheme, override the tokens by hand, or generate the roles once and keep the CSS.

To start from a Material Theme Builder export, pass its JSON to themeFromThemeBuilder(), or apply it live with themeOptionsFromThemeBuilder().

The seed (or the core primary) is the source, other core colors become palettes, extended colors become harmonized or exact customColors, and a variant or contrast field in the file is used if present. The generated schemes and palettes in the export are ignored, so the roles match the rest of labs/gb. A second argument overrides any option.

Dynamic color

Link to “Dynamic color” #

A dynamic scheme is generated from a source. The spec distinguishes user-generated color (a wallpaper or a person's pick, usually with the tonal-spot variant), content-based color (taken from an image or content on screen, with the content variant), and multiple sources (several schemes on one screen, each scoped to a region).

For content-based color, scope the scheme to one element with a source taken from an image:

To get the theme without applying it, use themeFromSource() or themeFromImage(img), and themeToStyleSheet(theme) for a stylesheet.

  • Variants: tonal-spot, neutral, vibrant, expressive, fidelity, content, monochrome, rainbow, and fruit-salad. The spec page does not define these variants or any version of their rules; they come from Material Color Utilities, which has 2025 rules only for tonal spot, neutral, vibrant and expressive. The others use the original rules, so labs/gb does too. theme.specVersion reports what was used.
  • Contrast: standard, medium, high, or a number from -1 to 1. applyTheme() accepts contrast: 'auto', which uses high contrast when the user prefers more contrast.
  • Platform: phone (also right for the web) or watch.
  • applyTheme(target, ...) accepts a document, a shadow root, or an element. An element gets inline custom properties, so its subtree has its own scheme. clearTheme() removes it.
  • Android's system-wide wallpaper source and the Material Theme Builder preview are not part of labs/gb; the library only generates the scheme.

When using content-based color, keep semantic colors (error, success) stable and make sure the surrounding UI stays readable if the image is very saturated or very dark. The scheme already guarantees accessible on-color pairs.

Advanced customization

Link to “Advanced customization” #

The spec lists three kinds of customization. This table shows what labs/gb covers.

Spec topic In labs/gb
Combine multiple color schemes Yes: call applyTheme(element, ...) on different elements, each with its own source, variant and contrast.
Map or remap colors on UI elements Yes: components read roles, so reassign a role in CSS (--md-sys-color-surface: var(--md-sys-color-surface-container);) on a subtree.
Define static colors Yes: customColors adds a color with four roles.
Define custom color roles Yes: customRoles takes a name, a palette and a tone for light and dark (optionally per contrast level).
Define your own baseline scheme Yes: override the static tokens, or pass palettes.
Define your own dynamic scheme Yes: palettes takes your own primary, secondary, tertiary, neutral, neutral variant and error key colors.
Use color fidelity Yes: fidelity per role.
Harmonize colors Yes: customColors harmonize toward the source by default, and harmonize(color, source) is exported.

Harmonize colors that carry meaning but should still sit in the theme, such as success and warning. Do not harmonize brand colors that must stay exact.

Custom color roles

Link to “Custom color roles” #

A custom role is one color picked from a palette at a reference tone, for light and dark, so it follows the source color and the contrast level like the built-in roles. It makes --md-sys-color-<name> only; pick a tone that meets contrast against the role it sits on (3:1 for graphics) and check the pair yourself.

palette is one of primary, secondary, tertiary, neutral, neutralVariant, error. Tones are 0 to 100; a number applies to both themes.

HCT

Link to “HCT” #

Colors in the system are built in HCT (hue, chroma, tone). To work in it yourself:

Colors outside the sRGB range are brought in by lowering chroma.

Prefer an existing role before adding custom colors, and keep contrast pairs accessible; customColors roles follow the same on-color convention as the accents.
